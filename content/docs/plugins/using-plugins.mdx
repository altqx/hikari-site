A **plugin** adds commands, panels and dialogs to HikariSub itself, through the Hikari API. It comes from the HikariSub marketplace, or as a single `.hikariplugin` file. Plugins are separate from [Automation scripts](/en/docs/automation/running-scripts), which work as before.

**Automation › Plugins** opens the plugin manager, where you find, install, update, turn on or off, set up and uninstall plugins. Its **Installed** view lists your plugins, and its **Marketplace** view the plugins you can add.

## Installing a plugin

### From the marketplace

1. Choose **Automation › Plugins**, then **Marketplace**.
2. Find a plugin with **Search plugins**, which matches the name, the summary and the author, or choose a category. Searching happens on your computer: see [What is sent](/en/docs/help/what-is-sent#plugins).
3. Choose a plugin to see what it does, its permissions, **What's new** in its latest version, the HikariSub version it needs, when it was last updated and its source.
4. Press **Install**. HikariSub downloads the plugin, checks it against the marketplace, and asks first, as below.

The question says the plugin is *Signed by* its author *and checked against the marketplace*, and lists what it asks for. A plugin with full trust asks you to install it only if you trust its author, because *it gets full access to your computer*, and its button reads **Install with full access**. A plugin made for a newer HikariSub says so, and can't be installed until you update HikariSub.

If the marketplace can't be reached, the view says why, with **Try again**.

### From the marketplace website

A plugin's page on the marketplace website, [marketplace.hikarisub.org](https://marketplace.hikarisub.org), has **Install in HikariSub**. It opens HikariSub at that plugin, in the plugin manager's **Marketplace** view, and starts HikariSub if it isn't running:

1. HikariSub downloads its own signed list of plugins again, and looks the plugin up in it. The link names only the plugin, and HikariSub trusts the list, not the website.
2. It downloads the plugin, checks it, and asks the install question, as **Install** does.

If you already have the newest version, it only shows the plugin. A plugin the list doesn't have, or one made for a newer HikariSub, gets *isn't in the marketplace for this HikariSub*.

If **Check for plugin updates** is off, HikariSub asks first, because it needs the list to check the plugin. **Turn on plugin updates** turns it on and carries on; **Close** installs nothing, and nothing is downloaded.

The button works where HikariSub registered `hikarisub://` links: the Windows installer, the AppImage, deb and rpm packages, and the portable tar.gz once you run `install-desktop-integration.sh` (see [Install](/en/docs/get-started/install#portable-targz)). The portable zip for Windows registers nothing. There, use **Download .hikariplugin** on the same page, and install the file as below.

### From a file

1. Choose **Automation › Plugins**, then **Install from file…**.
2. Pick the `.hikariplugin` file.
3. HikariSub checks the package and asks, for example, *Install “Line tools” 1.2.0?* It shows:
   - who signed it, if anyone (see [Trust](#trust));
   - what the plugin asks for: reading and editing every open subtitle file, connecting to network hosts, or a folder to read or to read and write, each with the plugin's reason. A plugin that asks for none of these works only on the active subtitle file.
   - *Runs programs that come with it*, with their names and the plugin's reason, and each program HikariSub would download for it, with its host and size. See [Programs](#programs).
   - *Set text in your Discord status*, with the plugin's reason. See [Discord status](#discord-status).
   - *Offers MCP servers in Settings › AI, off until you turn them on*, with their names. See [MCP servers](#mcp-servers).
   - **Full trust: it may run native code outside HikariSub's limits**, for an unrestricted plugin. Install one only if you trust its author completely.
4. Press **Install plugin**, or **Trust and install** when the signature needs your trust.

The same steps update a plugin, as does **Update from file…** in its details: HikariSub asks *Update “Line tools” from 1.2.0 to 1.3.0?*, and asks before it reinstalls a version or replaces one with an older version. A package HikariSub can't use, such as one with a broken manifest or a missing file, is not installed, and a message says why.

Plugins need a [user folder](/en/docs/automation/user-folder). A copy without one can't install them.

## Trust

A plugin installed from the marketplace shows **From the marketplace**: the marketplace's signed list vouches for its author's key, and each update must come from the same author.

The plugin manager and the marketplace website mark HikariSub's [own plugins](#hikarisubs-own-plugins) **By HikariSub**. Only plugins under the `hikarisub` handle signed with HikariSub's author key get it. It shows as an icon in the list, named when you hover, and as a badge beside the name in the details and on the website.

Every plugin installed from a file shows as **Unverified**, because HikariSub can't check where the file came from:

- **Unverified, unsigned:** the package isn't signed, so HikariSub can't tell who made it.
- **Unverified, signed by key** and a 16-digit key id: the author signed it. Updates must be signed by the same key.

When an update is signed by a different key, or comes unsigned over a signed install, HikariSub asks again before it installs it. A package that was changed after it was signed is always refused, whatever you choose.

## Managing plugins

The plugin manager is one window, which you can resize. The installed plugins are on the left, and the chosen plugin's details are on the right.

- **The list** shows each plugin's icon, name, version and signer. It also shows a state when the plugin isn't simply running: **Turned off**, **Didn't start**, **Stopped**, **Revoked**, an update that waits for you, such as **1.3.0 waits for you**, or **Full trust**. The Marketplace marks a plugin with full trust **Full trust** too. **Filter** matches the name, the author and the description. <kbd>Space</kbd> turns the chosen plugin on or off, and <kbd>Del</kbd> asks to uninstall it.
- **The details** say what the plugin does and who made it, its trust, the **Permissions** it asks for with each reason, and **What it adds**: its commands, panels, status bar items, [default shortcuts](#shortcuts), and the [colour themes and icon themes](#themes-and-icons-from-plugins) it brings. The **On** switch turns it on or off. A plugin that is off doesn't run, its commands leave the menu, and its panels show a [placeholder](#when-the-plugin-isnt-running).
- **Open in Settings…**, for a plugin that has settings, opens its page under **File › Settings › Plugins**. A change applies at once, and a running plugin uses it straight away.
- **Dev**, beside a plugin's name, marks a plugin its author runs from a folder while working on it. See [Work on it in place](/en/docs/plugins/write-your-first-plugin#work-on-it-in-place).
- **Programs**, for a plugin that comes with programs, shows each one's state, with **Download now** when one is missing. See [Programs](#programs).
- When a plugin didn't start, crashed or ran over its time limit, the details show the error and where it happened, with **Start again** and **Copy**.
- **Update from file…** updates the chosen plugin from a newer package. A package for a different plugin is refused.
- **Open data folder** opens the folder where the plugin keeps its data.
- **Remembered folders** lists the folders the plugin may use without asking. **Forget** drops one, and the plugin asks again the next time it needs it. See [Folders and files](#folders-and-files).
- **Uninstall…** removes the plugin after asking. If it has saved data, choose **Uninstall, keep its data**, to use it again if you reinstall, or **Uninstall and remove its data**.

A plugin's settings are kept when you update it, as long as they still fit the new version. A trusted Project can turn your plugins on or off, and change their settings, in its own window: see [Project plugins](/en/docs/basics/files-and-formats#project-plugins).

### Keeping plugins up to date

HikariSub checks the marketplace for new versions at start and once a day, and **Check for updates** checks at once. Plugins from the marketplace then update themselves, as long as both of these are ticked, which they are at first:

- **Install updates automatically** under **Plugin updates**, for every plugin;
- **Install updates automatically** in a plugin's details, for that plugin.

An update waits until the plugin isn't running a command, so nothing changes under it while it works. One that hasn't been installed when you quit is downloaded again at the next start. Plugins from a file never update themselves.

With either box clear, **Installed** shows how many plugins can be updated, such as **Installed 2**, and each one's details have **Update to** and the new version, such as **Update to 1.3.0**. Nothing updates until you press it.

To stop the daily check, clear **Check for plugin updates** under **Plugin updates**. It is on by default, and **Install updates automatically** works only while it is ticked.

#### An update that asks for more

An update never gives a plugin more access by itself. When a new version moves to full trust, asks for every open subtitle file, adds a network host, or adds a folder or wants to write to one, it waits for you. So does one that adds a program, lets a program connect to the internet, adds an MCP server or asks to set text in your Discord status. The list says, for example, **1.3.0 waits for you**, and the details say *1.3.0 asks for more than 1.2.0 does, so it waits for you.*, with **Review…**.

**Review…** asks first, as an install does. Each permission is marked **New** or **allowed now**, and the question shows the changes in the new version. Choose **Update plugin**, **Keep 1.2.0**, which passes over this version from then on, or **Cancel**.

#### Rolling back

When a plugin has been updated, its details have **Roll back to** and the version before, such as **Roll back to 1.2.0**. HikariSub keeps that one copy. Rolling back keeps the plugin's data, settings and remembered folders, and automatic updates then pass over the version you left. The notice *Line tools rolled back to 1.2.0* has **Undo**, which puts the newer version back.

#### Revoked plugins

The marketplace can revoke a version of a plugin, or the whole plugin. When it revokes the one you have, HikariSub then turns the plugin off, and a notice says *Line tools turned off*, with the reason and **Show**. The list says **Revoked**, and the plugin can't be turned on again. Its details say *The marketplace revoked version 1.3.0, so HikariSub turned it off*, with the reason, and offer:

- **Install** and the last version that wasn't revoked, such as **Install 1.2.0**, which turns the plugin back on;
- **Uninstall…**.

If the marketplace lifts the revocation, the mark goes, and the plugin stays off until you turn it on.

A plugin you installed from a file gets no updates from the marketplace. When the marketplace has the same plugin, signed with the same key, its details offer to move it there: **Move to the marketplace** installs the marketplace's copy, and from then on it gets updates. **Not now** hides the offer. Installing from a file over a marketplace plugin makes it a file install again.

## Running a plugin's commands

While a plugin runs, its commands sit in the **Automation** menu after **Plugins**, in a submenu named after the plugin.

A plugin can also put its commands in other menus: the Grid's right-click menu, the right-click menu of the Line editor's text, and the **Automation** menu itself, right after **Plugins**. Its rows come after HikariSub's own, with a separator between plugins, and hovering one names its plugin in the status bar. A command that can't run yet is greyed out, with the reason under it, such as *Needs a selection* or *Needs an open video*. Its key does nothing until then either.

### Status bar items

A plugin can show up to four items at the end of the status bar, as text, an icon or both, such as a count it keeps up to date. Hovering one shows the plugin's name with what the item is. Clicking an item that has a command runs it.

To hide an item, right-click the status bar and clear its row. The menu lists every plugin item by name, and ticking the row shows the item again. A plugin's items go when it stops.

### Shortcuts

To give a plugin command a shortcut, open **File › Settings › Shortcuts** and choose the **Plugin shortcuts** filter. A plugin command's shortcut works everywhere. A shortcut for a plugin that is uninstalled or turned off stays listed with a note, ready for when the plugin comes back.

A plugin can come with default shortcuts. Each works while the plugin runs, unless:

- you gave that command a shortcut of your own, or cleared its shortcut. A default you clear stays cleared.
- the key is taken, by a shortcut of yours, by HikariSub or by a plugin you installed earlier. The key stays theirs, and the plugin's details in the plugin manager say who has it, such as *Ctrl+Alt+K is taken by* and the name of the command or plugin that has it.

### Lists and questions

A plugin can ask you to pick from a list or to type a value, in a popup of HikariSub's own. Its title row always names the plugin, so you can tell it from HikariSub's questions.

- **A list** filters as you type. Where you can pick several, each row has a check box, the popup counts them, such as *2 picked*, and **OK** takes them.
- **A text box** can say what's wrong with what you typed before you press <kbd>Enter</kbd>. For a password it shows dots, with **Show** and **Hide**.
- **Several steps** can have **Back**, or <kbd>Alt</kbd>+<kbd>←</kbd>, to go to the step before.
- <kbd>Esc</kbd>, or a click outside, cancels.

A plugin can open one only in answer to something you did, such as a command you ran or a click in its own panel or dialog. So a popup never takes the focus by itself. Only one shows at a time: opening another closes the one that was showing. A plugin's popup also closes when the plugin stops.

## Help as you type

A plugin can help in the [Line editor](/en/docs/basics/line-editor)'s text, and in the translation in translation mode:

- **Suggestions.** They join HikariSub's tag list in one popup, after the tags, each with what it is and the plugin's name. The popup opens when you type `\` or a character the plugin listens for, or with **Trigger completion**, <kbd>Ctrl</kbd>+<kbd>Space</kbd>. <kbd>Enter</kbd> or a click puts the suggestion in. With no plugin answering, the tag list is the same as before.
- **Hovers.** Rest the pointer on the text, and what a plugin says about it shows as a tooltip, followed by `·` and the plugin's name.

A plugin that takes longer than a second to answer is left out of that popup or tooltip, and keeps running.

## Problems from plugins

A plugin can point out problems in your lines, each an error, a warning, a note or a hint, sometimes with quick fixes. They show in three places:

- **The [Problems](/en/docs/checking/qc-notes) panel**, which also holds the QC notes, groups them by line. Choosing one selects its line and seeks the video to it. A problem's quick fixes are in its menu.
- **The Line editor** underlines each one with a wavy line in its severity's colour, or a dotted line for a hint. Hovering it shows the message and where it comes from. **Quick fix**, <kbd>Alt</kbd>+<kbd>Enter</kbd>, offers the fixes for the problem at the caret.
- **The Grid** marks a row that has problems, in the colour of the worst one, and its tooltip counts them.

A quick fix is one undo step, named after where the problem comes from and the fix. Problems aren't saved in the file. A plugin's problems on a line go when you change that line's text, until the plugin checks it again, and all of them go when the plugin stops.

## Plugin panels

A plugin can add panels of its own, such as a list of lines to check or a chart. They work like HikariSub's panels: they dock, tab and float, and keep their place in your [layouts](/en/docs/customize/layouts).

- **View › Panels** lists them after HikariSub's own panels, sorted by title, with the plugin's name beside each. Each has **Show**, **Float** or **Dock**, and **Close**.
- A plugin panel stays closed until you show it or the plugin opens it. It first opens where the plugin suggests: in the left or right [side bar](/en/docs/customize/layouts#side-bars), or along the bottom of the window. After that it opens wherever you left it.
- Its **⋯** menu starts with the plugin's own items, and has **About** and the plugin's name, such as **About Line tools**, which opens the plugin manager at that plugin.
- Hovering the panel's header names the plugin it comes from, such as *Timing check, from Line tools*.

A plugin with full trust can draw a panel itself, instead of with HikariSub's controls. Its install question and permissions then say *Shows its own panels inside HikariSub*. The panel docks, tabs and floats like any other, and loads the first time you show it.

### When the plugin isn't running

A layout keeps a plugin panel's place even when its plugin can't run. The panel says why, with the button that helps:

- *Line tools isn't installed.* **Open Plugins…** opens the plugin manager.
- *Line tools is turned off.* **Turn on** turns it on.
- *Line tools stopped.* or *Line tools didn't start.* **Start again** starts it, and **Details** opens the [Log panel](/en/docs/help/troubleshooting#the-log-panel).

If a panel the plugin draws itself can't load, it says *The panel couldn't load.*, with the first error, **Copy** and **Load again**. The whole error goes to the Log panel. The plugin's other panels keep working.

Such a panel runs inside HikariSub, so a fault in it can close or freeze HikariSub. If HikariSub closed while one was open, that plugin's panels say that HikariSub closed while the plugin's panel was open, and stay closed, even after later restarts, until you choose **Load again** in one of them.

When the plugin is back, its panel fills the place again. To forget the place, close the panel of a plugin that isn't installed, or choose **Remove from the layout** under the panel in **View › Panels**.

## Styles, presets and more from plugins

A plugin can also bring things that work without its code: style catalogues, karaoke presets, node-effect graphs, spelling dictionaries and layouts. Each shows beside HikariSub's own, with the plugin's name, and is read-only. They go when you turn the plugin off or uninstall it.

| A plugin's | Shows in |
| --- | --- |
| Style catalogues | The [Style manager](/en/docs/basics/styles#catalogues)'s **Catalogue** list, under *From plugins*. **Copy to my catalogues** makes a copy you can change. |
| Karaoke presets | The Template editor's **New › From a preset**, after the built-in presets: see [Presets from plugins](/en/docs/karaoke/presets#presets-from-plugins). |
| Node-effect graphs | **From the library** in node effects, in a submenu named after the plugin: see [The library](/en/docs/karaoke/node-effects#the-library). |
| Spelling dictionaries | The spell checker's languages, such as **Primary language**: see [Dictionaries](/en/docs/checking/spelling#dictionaries). |
| Layouts | **View › Layout**, the layout button and **Manage layouts**: see [Layouts from plugins](/en/docs/customize/layouts#layouts-from-plugins). |

A package whose content HikariSub can't read isn't installed, and the message names the file.

### Themes and icons from plugins

A plugin can also change how HikariSub looks:

- **Colour themes** are listed in **File › Settings › Appearance** after the built-in themes. See [Themes](/en/docs/customize/themes).
- **Icon themes** replace HikariSub's interface icons. Once a plugin that's on has one, **File › Settings › Appearance** gets an **Icons** section. Its **Icons** row offers **HikariSub**, the default, and each icon theme, named with its plugin. The change applies at once. Icons a theme doesn't cover show HikariSub's own.
- **Its own icons** can show on the plugin's commands and status bar items, coloured like HikariSub's own icons.

When you turn the plugin off or uninstall it, a window showing one of its colour themes goes back to the built-in theme of the same type, and **Icons** goes back to **HikariSub**.

A plugin that brings only content like this, with no code, runs nothing. Its install question shows what it adds and who signed it, with no permissions to agree to.

## Subtitle formats from plugins

A plugin can add subtitle formats of its own.

- **Writing.** A format the plugin can write shows in **File › Export as…**, after the built-in formats, and in the file types of **File › Save as…**, as its title with the plugin's name in brackets. The plugin makes the file, and HikariSub writes it.
- **Opening.** A format it can read opens with **File › Open subtitles…** and by dragging the file onto the window, as an ASS file. HikariSub tries its own formats first, then the plugins' formats, in the order you installed the plugins, and the first that reads the file wins. Choosing a plugin's format in the open window's file types tries only that one.
- **Saving.** A file opened through a plugin saves back through it when the plugin can also write the format. Otherwise, use **Save as…**.

A plugin's format reads and writes files of up to 48 MiB. While the plugin isn't running, its formats can't open or save, and a notice says so.

## Folders and files

A plugin works on your subtitles through HikariSub, and keeps its own data in a folder of its own. For anything else on your computer, it asks:

- **A folder:** the first time the plugin needs one, HikariSub asks, for example *Line tools asks for a folder to read: Font folder*, with the plugin's reason. **Choose folder…** picks it. **Remember this folder for Line tools**, ticked at first, lets the plugin use it from then on without asking, until you **Forget** it in the plugin manager or uninstall the plugin. Otherwise the plugin keeps the folder until it stops. A folder it asked to read only stays read-only.
- **Your Project's folder:** while you work in a [Project](/en/docs/basics/files-and-formats#projects) whose folder you trust, every plugin can read and write the files in it, without asking. In a Project you haven't trusted, plugins can't open it.
- **Your git repository:** a plugin that asks for it can read the branches, tags and history of the git repository holding your subtitle files, read-only. The install question, the plugin manager and the marketplace show it as *Read the branches, tags and history of the git repository holding your subtitle files:* and the plugin's reason. HikariSub runs git for the plugin, and never fetches anything.
- **A file:** the plugin can open the file window, titled with its name, such as *Line tools: choose a file*, or take files you drop on its panel. It gets only the file you pick or drop. When the plugin asks where to save a file, HikariSub's own file window starts with the name the plugin suggests, and a full path you type as the name saves to exactly that path.

## The internet

A plugin can connect only to the hosts it listed, which the install question and its permissions show, and only over HTTPS. HikariSub makes each request for it. **File › Settings › Updates and privacy › Privacy › Let plugins connect to the internet**, on by default, turns this off for every plugin at once. A plugin with full trust isn't held to these limits. [What is sent](/en/docs/help/what-is-sent#plugins) has the details, and what the marketplace downloads.

## Programs

Some plugins come with programs of their own, or are a program, written in any language. The install question then says *Runs programs that come with it*, with their names and the plugin's reason.

A program comes inside the plugin's package, or HikariSub downloads it for the plugin:

- **When.** The first time the plugin starts without it: after you install or update the plugin, or after a download that failed.
- **What is checked.** HikariSub downloads only over HTTPS, and checks the file's size and SHA-256 against the ones the plugin's signed package names before it unpacks anything. An archive is unpacked with strict limits, and never with links.
- **The install question** lists each download, such as *Downloads* and the program's name, *from* its host, with its size.
- **Where it goes.** Into `plugin-programs` in your [user folder](/en/docs/automation/user-folder). HikariSub keeps the copies the installed version and the version kept for [rolling back](#rolling-back) need, and removes a plugin's programs when you uninstall it.
- **The internet switch.** Nothing is downloaded while **File › Settings › Updates and privacy › Privacy › Let plugins connect to the internet** is off.

The plugin's details list its **Programs**, each with its state: *isn't downloaded*, *Downloading…*, or why a download failed. **Download now** tries again, for example after you turn **Let plugins connect to the internet** back on.

A program may be made only for some computers. One with no version for yours shows *isn't available for this computer*, and what needs it doesn't work there. A plugin that is itself such a program doesn't install there. In the **Marketplace**, a plugin with no package for your computer says **Not available for this computer**, and has no **Install**.

### How programs run

- **Their own sandbox.** Each program runs in an operating-system sandbox of its own, even for a plugin with full trust. It reads its own files, keeps its data in the plugin's own folders, and works on the files you hand it.
- **Windows.** A program runs in an AppContainer. A plugin may ask for low integrity instead, for programs that can't run in one. Its install question then adds *Can read your files*.
- **The internet.** A program has none, unless the plugin asks for it, and the install question then says *Connects to the internet*. While **Let plugins connect to the internet** is off, such a program starts without it, and one that runs at low integrity doesn't start at all.
- **Never unconfined.** Where the sandbox can't apply, the program doesn't start, and the plugin's details say why.
- **Stopping.** A program ends when its plugin stops, is turned off, updated or uninstalled. What it writes as errors goes to the [Log panel](/en/docs/help/troubleshooting#the-log-panel) under the plugin's name.

## MCP servers

A plugin can bring [MCP servers](/en/docs/ai/agent#mcp-servers), which give the agent more tools. Its install question says *Offers MCP servers in Settings › AI, off until you turn them on*, with their names.

Each one shows in **File › Settings › AI › MCP › MCP servers** as its name with the plugin's name in brackets, and *From a plugin, in its sandbox*. It has an **On** switch in place of **Edit** and **Delete**, and stays off until you turn it on. Its tools follow the same rules as those of a server you add, and what it says about its tools isn't trusted at first. It runs as one of the plugin's [programs](#how-programs-run), in its sandbox.

Turning the plugin off takes the server out of every thread. Uninstalling the plugin also forgets that you turned the server on.

## Discord status

A plugin can ask to *Set text in your Discord status*, with its reason, such as the episode your team's tracker knows. Its text shows only where you put `{plugin}` in your own presence text, and only from the one plugin you choose in **File › Settings › Updates and privacy › Discord › Text from plugin**. It is plain text of at most 64 characters, and shows only while Discord presence is on. See [Discord presence](/en/docs/help/what-is-sent#discord-presence).

## Safety and limits

- Each plugin runs in a process of its own, so a plugin that crashes ends only itself. HikariSub and your other plugins keep running. The plugin's next command starts it again.
- A command that runs longer than 10 seconds isn't stopped. A card above the status bar says, for example, *Line tools is still working*, with **Stop**, which ends the plugin; its next command starts it again. A long job, such as scanning a video, instead shows a card with its progress and **Cancel**. If the plugin hasn't stopped 5 seconds after **Cancel**, the card offers **Stop**, which ends it; work it hasn't applied is lost.
- A plugin whose install question says *Works in the background while HikariSub is open*, with its reason, starts with HikariSub and can do things on a timer. While one works, the status bar shows how many plugins are working, such as *1 plugin working*. Click it for the list, with **Stop** for each. A plugin stopped there stays stopped until **Start again** in its details, or the next time HikariSub starts.
- A plugin may use up to 2 GB of memory. A command that needs more fails, and the plugin keeps running.
- An ordinary (restricted) plugin can't load native libraries or compiled Lua bytecode, and has no access to files, programs or the system beyond what HikariSub gives it.
- On Linux and Windows, an ordinary plugin runs in an operating-system sandbox. It reaches only its own package and has no network of its own: HikariSub opens the files you give it and makes its requests. Where the system can't provide the sandbox, the plugin still runs under these limits, and its details say *HikariSub keeps it to these permissions, but it isn't sandboxed on this system.*

A plugin with full trust runs outside the sandbox, with the same access as HikariSub, so install those only from authors you trust.

## When something goes wrong

- When a command fails, a notice shows its error. Its details say more.
- When a plugin fails to start, a notice says it didn't start, and its details hold the error.
- Errors in a plugin's background handlers go to the [Log panel](/en/docs/help/troubleshooting#the-log-panel).

## HikariSub's own plugins

These plugins come from HikariSub itself. They are on the marketplace, marked **By HikariSub**, and install like any other plugin.

### Macro chains

[Macro chains](https://marketplace.hikarisub.org/plugins/hikarisub.macro-chains) records a chain of HikariSub commands and Automation macros, with the answers you gave their dialogs, and runs it again as one undo step. It was inspired by [AegisubChain](https://github.com/arch1t3cht/AegisubChain) by arch1t3cht.

- **Recording:** in the **Macro chains** panel (**View › Panels**), choose **Record a chain**, or run the *Record a chain* command, and work as usual. Each macro and command that applies becomes a step, with what you answered in its dialogs. Undo while recording takes the last step back. Name the chain and choose **Stop and save**.
- **Editing:** **Edit** sets, for each step, the selection after it (the macro's own, the one from before, or the lines it changed), whether its dialogs show every time, and each dialog field as **Constant**, **Ask** or **Exclude**. Steps move up and down and can be removed. A chain can take one of five slots, *Run chain slot 1* to *5*, which take keys in **File › Settings › Shortcuts**.
- **Running:** **Run**, or the chain's slot command, asks every Ask field in one dialog first, then runs the chain as one undo step. If a step fails, the chain stops there, and **Undo the chain** takes back the steps that ran.
- **Importing AegisubChain chains:** **Import AegisubChain chains…** reads AegisubChain's configuration file, `arch.AegisubChain.json` in Aegisub's DependencyControl config folder, or a file of exported chains, and shows what it found before adding anything. An imported chain shows each of its dialogs once, filled in, the first time it runs, and learns them. A step whose macro isn't loaded stays until its script is.
- **Where chains are kept:** in `chains.json`, in the plugin's own data folder. It asks for no permissions.

### Keyframe generator

[Keyframe generator](https://marketplace.hikarisub.org/plugins/hikarisub.keyframe-generator) finds the scene changes in the open video and makes keyframes from them. Open its panel from **View › Panels › Keyframe generator**, or run **Find keyframes** from its submenu under **Automation**. **Sensitivity** (0 to 100, from *Fewer cuts* to *More cuts*) and **Minimum gap** (frames) set what counts as a cut. **Find keyframes** reads every frame of the video as a background job, with a card above the status bar and **Cancel**; the keyframes you have stay until you set the new ones. Then **Set keyframes** makes them the video's keyframes, and **Save as keyframes file…** saves an Aegisub keyframes file. It asks for no permissions.

### Git line marks

[Git line marks](https://marketplace.hikarisub.org/plugins/hikarisub.git-line-marks) shows what changed in a subtitle file since a git branch, tag or commit, right in the Grid. In its panel (**View › Panels › Git line marks**), pick a branch, tag or recent commit, or type a revision such as `HEAD~2`. Lines added since then get a green mark, changed, moved or retimed ones an amber mark, and a red mark shows where lines were removed. Hovering a mark names the change, and the panel lists every marked line; double-click one to select it in the Grid. The marks refresh after each save while **Refresh when I save** is on, which it is at first. They are never written into the file. **Automation › Git line marks** has **Refresh git line marks** and **Clear git line marks**.

It works on ASS files saved in a git repository, with git on your `PATH` (Git for Windows on Windows). Its install question asks to *Read the branches, tags and history of the git repository holding your subtitle files: Compares your subtitle file with the branch, tag or commit you pick, to mark the Lines that changed since then.* HikariSub runs git for it, read-only.

## Writing plugins

The [agent](/en/docs/ai/agent#plugins) can write a plugin for you. Installing one it wrote always asks first, in every mode, with the same details as installing from a file, and the plugin's code. Running a plugin's command from the agent asks too.

[Write your first plugin](/en/docs/plugins/write-your-first-plugin) makes a small plugin step by step, and the [Hikari API reference](/en/docs/plugins/api-reference) lists every operation and event. The full plugin format, the manifest, signing and the `hikari` API for plugin authors are in [docs/plugins.md](https://github.com/altqx/hikari/blob/main/docs/plugins.md) in HikariSub's repository. Its [Panels and dialogs](https://github.com/altqx/hikari/blob/main/docs/plugins.md#panels-and-dialogs) section covers panels, their widgets and dialogs, with a sample plugin, and [QML panels](https://github.com/altqx/hikari/blob/main/docs/plugins.md#qml-panels) the panels a full trust plugin draws itself.
