A **plugin** adds commands, panels and dialogs to HikariSub itself, through the Hikari API. It comes from the HikariSub marketplace, or as a single `.hikariplugin` file. Plugins are separate from [Automation scripts](/en/docs/automation/running-scripts), which work as before.

**Automation › Plugins…** opens the plugin manager, where you find, install, update, turn on or off, set up and uninstall plugins. Its **Installed** view lists your plugins, and its **Marketplace** view the plugins you can add.

## Installing a plugin

### From the marketplace

1. Choose **Automation › Plugins…**, then **Marketplace**.
2. Find a plugin with **Search plugins**, which matches the name, the summary and the author, or choose a category. Searching happens on your computer: see [What is sent](/en/docs/help/what-is-sent#plugins).
3. Choose a plugin to see what it does, its permissions, **What's new** in its latest version, the HikariSub version it needs, when it was last updated and its source.
4. Press **Install**. HikariSub downloads the plugin, checks it against the marketplace, and asks first, as below.

The question says the plugin is *Signed by* its author *and checked against the marketplace*, and lists what it asks for. A plugin with full trust asks you to install it only if you trust its author, because *it gets full access to your computer*, and its button reads **Install with full access**. A plugin that needs a newer HikariSub says so instead of **Install**.

If the marketplace can't be reached, the view says why, with **Try again**.

### From a file

1. Choose **Automation › Plugins…**, then **Install from file…**.
2. Pick the `.hikariplugin` file.
3. HikariSub checks the package and asks, for example, *Install “Line tools” 1.2.0?* It shows:
   - who signed it, if anyone (see [Trust](#trust));
   - what the plugin asks for: reading and editing every open subtitle file, connecting to network hosts, or a folder to read or to read and write, each with the plugin's reason. A plugin that asks for none of these works only on the active subtitle file.
   - **Full trust: it may run native code outside HikariSub's limits**, for an unrestricted plugin. Install one only if you trust its author completely.
4. Press **Install plugin**, or **Trust and install** when the signature needs your trust.

The same steps update a plugin, as does **Update from file…** in its details: HikariSub asks *Update “Line tools” from 1.2.0 to 1.3.0?*, and asks before it reinstalls a version or replaces one with an older version. A package HikariSub can't use, such as one with a broken manifest or a missing file, is not installed, and a message says why.

Plugins need a [user folder](/en/docs/automation/user-folder). A copy without one can't install them.

## Trust

A plugin installed from the marketplace shows **From the marketplace**: the marketplace's signed list vouches for its author's key, and each update must come from the same author.

Every plugin installed from a file shows as **Unverified**, because HikariSub can't check where the file came from:

- **Unverified, unsigned:** the package isn't signed, so HikariSub can't tell who made it.
- **Unverified, signed by key** and a 16-digit key id: the author signed it. Updates must be signed by the same key.

When an update is signed by a different key, or comes unsigned over a signed install, HikariSub asks again before it installs it. A package that was changed after it was signed is always refused, whatever you choose.

## Managing plugins

The plugin manager is one window, which you can resize. The installed plugins are on the left, and the chosen plugin's details are on the right.

- **The list** shows each plugin's icon, name, version and signer. It also shows a state when the plugin isn't simply running: **Turned off**, **Didn't start**, **Stopped** or **Full trust**. **Filter** matches the name, the author and the description. <kbd>Space</kbd> turns the chosen plugin on or off, and <kbd>Del</kbd> asks to uninstall it.
- **The details** say what the plugin does and who made it, its trust, the **Permissions** it asks for with each reason, and **What it adds**: its commands and panels. The **On** switch turns it on or off. A plugin that is off doesn't run, its commands leave the menu, and its panels show a [placeholder](#when-the-plugin-isnt-running).
- **Settings**, for a plugin that has them, is a form of check boxes, fields and drop-down lists. A change is kept at once, and a running plugin uses it straight away.
- When a plugin didn't start, crashed or ran over its time limit, the details show the error and where it happened, with **Start again** and **Copy**.
- **Update from file…** updates the chosen plugin from a newer package. A package for a different plugin is refused.
- **Open data folder** opens the folder where the plugin keeps its data.
- **Remembered folders** lists the folders the plugin may use without asking. **Forget** drops one, and the plugin asks again the next time it needs it. See [Folders and files](#folders-and-files).
- **Uninstall…** removes the plugin after asking. If it has saved data, choose **Uninstall, keep its data**, to use it again if you reinstall, or **Uninstall and remove its data**.

A plugin's settings are kept when you update it, as long as they still fit the new version.

### Keeping plugins up to date

HikariSub checks the marketplace for new versions at start and once a day. **Installed** then shows how many plugins can be updated, such as **Installed 2**, and each one's details have **Update to** and the new version, such as **Update to 1.3.0**. Nothing updates until you press it. **Check for updates** checks at once.

To stop the daily check, clear **Check for plugin updates** under **Plugin updates**. It is on by default.

A plugin you installed from a file gets no updates from the marketplace. When the marketplace has the same plugin, signed with the same key, its details offer to move it there: **Move to the marketplace** installs the marketplace's copy, and from then on it gets updates. **Not now** hides the offer. Installing from a file over a marketplace plugin makes it a file install again.

To give one a shortcut, open **File › Settings › Shortcuts** and choose the **Plugin shortcuts** filter. A plugin command's shortcut works everywhere. A shortcut for a plugin that is uninstalled or turned off stays listed with a note, ready for when the plugin comes back.

## Plugin panels

A plugin can add panels of its own, such as a list of lines to check or a chart. They work like HikariSub's panels: they dock, tab and float, and keep their place in your [layouts](/en/docs/customize/layouts).

- **View › Panels** lists them after HikariSub's own panels, sorted by title, with the plugin's name beside each. Each has **Show**, **Float** or **Dock**, and **Close**.
- A plugin panel stays closed until you show it or the plugin opens it. It first opens where the plugin suggests, as a tab beside the panel there, and after that wherever you left it.
- Its **⋯** menu starts with the plugin's own items, and has **About** and the plugin's name, such as **About Line tools…**, which opens the plugin manager at that plugin.
- Hovering the panel's header names the plugin it comes from, such as *Timing check, from Line tools*.

A plugin can also open dialogs of its own, with up to four buttons.

### When the plugin isn't running

A layout keeps a plugin panel's place even when its plugin can't run. The panel says why, with the button that helps:

- *Line tools isn't installed.* **Open Plugins…** opens the plugin manager.
- *Line tools is turned off.* **Turn on** turns it on.
- *Line tools stopped.* or *Line tools didn't start.* **Start again** starts it, and **Details** opens the [Log panel](/en/docs/help/troubleshooting#the-log-panel).

## Folders and files

A plugin works on your subtitles through HikariSub, and keeps its own data in a folder of its own. For anything else on your computer, it asks:

- **A folder:** the first time the plugin needs one, HikariSub asks, for example *Line tools asks for a folder to read: Font folder*, with the plugin's reason. **Choose folder…** picks it. **Remember this folder for Line tools**, ticked at first, lets the plugin use it from then on without asking, until you **Forget** it in the plugin manager or uninstall the plugin. Otherwise the plugin keeps the folder until it stops. A folder it asked to read only stays read-only.
- **A file:** the plugin can open the file window, titled with its name, such as *Line tools: choose a file*, or take files you drop on its panel. It gets only the file you pick or drop.

## The internet

A plugin can connect only to the hosts it listed, which the install question and its permissions show, and only over HTTPS. HikariSub makes each request for it. **File › Settings › Updates and privacy › Privacy › Let plugins connect to the internet**, on by default, turns this off for every plugin at once. A plugin with full trust isn't held to these limits. [What is sent](/en/docs/help/what-is-sent#plugins) has the details, and what the marketplace downloads.

## Safety and limits

- Each plugin runs in a process of its own, so a plugin that crashes ends only itself. HikariSub and your other plugins keep running. The plugin's next command starts it again.
- A command that runs longer than 10 seconds is stopped, and a notice says so. The plugin's next command starts it again.
- A plugin may use up to 256 MB of memory. A command that needs more fails, and the plugin keeps running.
- An ordinary (restricted) plugin can't load native libraries or compiled Lua bytecode, and has no access to files, programs or the system beyond what HikariSub gives it.

These limits come from running each plugin in its own process. They are not an operating-system sandbox, so install plugins only from authors you trust.

## When something goes wrong

- When a command fails, a notice shows its error. Its details say more.
- When a plugin fails to start, a notice says it didn't start, and its details hold the error.
- Errors in a plugin's background handlers go to the [Log panel](/en/docs/help/troubleshooting#the-log-panel).
