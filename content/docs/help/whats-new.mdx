### Projects and the Explorer

- **Open a folder as a Project:** **File › Open folder…**, **Open folder…** on the Home page, dropping a folder, or `hikarisub <folder>` opens it as the window's Project, and **File › Close project** closes its tabs and keeps them for **Reopen last tabs**. The **Explorer** panel, in **View › Explorer**, shows the Project's folder, where you can open, rename, trash or add subtitle files. See [Projects](/en/docs/basics/files-and-formats#projects) and [the Explorer](/en/docs/basics/projects#the-explorer).
- **Project settings:** while a folder is open as a Project, **File › Settings** has a **Yours** tab and a **Project** tab, which holds the spelling and grammar, Tags from original, Script properties and Translation values saved in `.hikari/project.toml`, with your own changes in `.hikari/project.local.toml`. Each row says where its value comes from, and **Use yours** clears the Project's value. See [The Project tab](/en/docs/basics/files-and-formats#the-project-tab).
- **Project tiers:** a Project can keep its own style catalogues, font catalogues, layouts, shapes, tags, and script dialog, Shift times and Timing postprocessor presets in its `.hikari` folder. Each list shows *This project* before *Mine* and copies or moves items between the two, and while a Project is open, saving goes to the Project at first. See [Project tiers](/en/docs/basics/project-tiers).
- **A Project's dictionary, export format and languages:** a Project can keep its own dictionary words in `.hikari/dictionary.txt`, which count only in its windows, and **Add to dictionary** lets you choose the Project's dictionary or your own. The Project tab's **Export** page sets the format for files not exported yet, and its **Translation** page sets the languages **Translate to** uses. See [Project tiers](/en/docs/basics/project-tiers#dictionary-words).
- **Project fonts:** list font folders in `.hikari/project.toml`, such as `fonts = ["fonts", "../common/fonts"]`, and every subtitle file in the Project's window draws with them, after the fonts attached to the file and before your Fonts folder and installed fonts. The font picker, the Style manager and the Font collector use them too. See [Project fonts](/en/docs/basics/files-and-formats#project-fonts).
- **Project scripts and plugin settings:** a trusted Project can bring its own Automation scripts and modules in `.hikari/automation/`, which replace yours of the same name only in its window, and `[plugins]` in `.hikari/project.toml` turns your plugins on or off and changes their settings. When a Project uses a plugin you don't have, the plugin manager offers **Install from the marketplace**. See [Project scripts](/en/docs/basics/files-and-formats#project-scripts).
- **A Project's own AI keys:** in a trusted Project's window, **File › Settings › Project › AI** names an environment variable or a `.hikari/credentials.toml` entry for each of your providers, and **Create credentials file** makes the file and a `.hikari/.gitignore` that keeps it out of git. A key found in `project.toml` is ignored, with an offer to move it. See [Project AI keys](/en/docs/basics/files-and-formats#project-ai-keys).
- **Open a folder from Windows Explorer or the Linux launcher:** the Windows setup's file associations add **Open with HikariSub** to a folder's right-click menu, under **Show more options** on Windows 11. On Linux, HikariSub's launcher menu has **Open Folder…**, and `--open-folder` shows the Open folder picker. See [Opening a folder](/en/docs/basics/files-and-formats#opening-a-folder).
- **Trusted folders moved to General:** **File › Settings › Automation › Trusted script folders** is now **File › Settings › General › Trusted folders**, with the same folders. A trusted folder covers the folders inside it, and a file inside a Project there opens the Project. See [Scripts a subtitle file names](/en/docs/automation/running-scripts#scripts-a-subtitle-file-names).
- **A tab moved into a Project says so:** moving a tab to a window with a Project shows *This tab now uses the project My Show.*, and the tab uses that Project. See [Moving a tab to another window](/en/docs/customize/layouts#moving-a-tab-to-another-window).

### Side bars

- **Side bars:** an AI side bar on the left holds the Agent and Review panels, and a tools side bar on the right holds the Explorer, Find, Shift times, the Timing postprocessor, Styles and QC notes; move any tool panel into one from its **⋯** menu, toggle them from the title bar, the **View** menu or <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>B</kbd>, and switch their edges with **View › Swap side bars**. On the first start, panels docked right of the Grid move into the side bars once, and windows narrower than 2140 px start with the tools side bar alone. See [Side bars](/en/docs/customize/layouts#side-bars).
- **Lock your layout:** **View › Layout › Lock layout**, also in the layout switcher and each panel's **⋯** menu, keeps every panel where it is, and you can still resize panels by their edges. The lock is kept with the tab, the session and saved layouts. See [Locking the layout](/en/docs/customize/layouts#locking-the-layout).
- **Panels open where you can find them:** a panel that has no place in your layout now opens in a column to the right of the Grid, and panels opened after it join that column as tabs. Panels that have their own place keep it, and layouts you saved earlier are unchanged. See [Where a panel opens](/en/docs/customize/layouts#where-a-panel-opens).
- **Resize two panels at once:** drag where the lines between panels meet, and every line that meets there moves with the pointer. Floating panels now resize from each of their edges and corners. See [Moving panels](/en/docs/customize/layouts#moving-panels).
- **Drag a floating panel back from anywhere on its header:** on Linux, pressing the title or the empty part of a floating panel's header picks it up and docks it where you let go, as on Windows. On Wayland the panel steps out of the way while you drag. See [Floating panels](/en/docs/customize/layouts#floating-panels).

### Several windows

- **More than one window:** drag a tab out of the tab row into a new window or onto another window's tab row, or use **Move tab to new window** and **Move tab to window ›**. Each window has its own tabs, panels and layout, closing a window asks only about its own changes, and sessions bring back every window. See [Windows](/en/docs/customize/layouts#windows).
- **Video and audio in each window:** each window plays its own tab's video and audio, and keeps its frame while you work in another. Playing in one window pauses the others, and each window goes full screen on its own. See [What each window has](/en/docs/customize/layouts#what-each-window-has).
- **Notices in their own window:** a notice or question about a tab shows in that tab's window, and notices about HikariSub as a whole show once, in the window you used last. A crash report now also says how many windows were open, how many tabs each had and which was active, and nothing more about them. See [Crash and freeze reports](/en/docs/help/what-is-sent#crash-and-freeze-reports).
- **Alt+F4 closes only its window:** <kbd>Alt</kbd>+<kbd>F4</kbd> runs the new **Close window** command, also in **File › Close window**, and no other command can take it. **File › Exit** still closes every window but has no key at first, and importing legacy settings moves an Exit on <kbd>Alt</kbd>+<kbd>F4</kbd> to Close window. See [Closing windows](/en/docs/customize/layouts#closing-windows).
- **The window comes back as you left it:** quitting, loading the last session or recovering from a crash brings each window back where it was, at its size, with its tabs in order and the same tab in front. On Wayland, only the size and maximised state come back. See [Sessions](/en/docs/basics/files-and-formats#sessions).

### Hikari AI and agents

- **The Agent panel:** ask HikariSub's AI agent to work on your subtitles, in threads, and its edits wait in the Review panel. Each thread has a mode, Manual, Auto or Full access, risky actions ask in every mode, and each thread and each day have a cost cap, $2.00 and $10.00 at first. See [The Agent panel](/en/docs/ai/agent).
- **Claude Code and Codex in the Agent panel:** with Claude Code or Codex installed, the Agent panel is ready without a provider, and a thread runs on your own `claude` or `codex` with only HikariSub's tools, its edits waiting in the review. The first time, HikariSub downloads the Claude Agent SDK from npm and checks it. See [Agents on this computer](/en/docs/ai/agent#agents-on-this-computer).
- **ACP agents:** **File › Settings › AI › External agents** runs ACP agents: HikariSub finds OpenCode and Antigravity on your `PATH`, and **Add agent** adds any other. Each agent writes only to its own folders, and their edits go to the review. See [ACP agents](/en/docs/ai/agent#acp-agents).
- **Codex and ACP agents on Windows:** they run with low rights instead of in an app container, can read your files but write only their own folders, and change your subtitles only through HikariSub's tools. HikariSub now keeps your AI keys and sign-ins on Windows in a private folder instead of Windows Credential Manager. See [On Windows](/en/docs/ai/agent#on-windows).
- **Connect Claude Code or Codex through MCP:** **File › Settings › AI › MCP › Let agents outside HikariSub edit through MCP** lets an agent you run yourself read and edit your open files, and **Copy setup** copies what it needs. Every edit waits in the new **Review panel** until you **Keep** or **Undo** it, and **Reset token** makes a new token at once. See [Connect Claude Code or Codex](/en/docs/ai/connect-an-agent) and [Reviewing AI changes](/en/docs/ai/review).
- **Proposals in Manual mode:** the agent's subtitle edits come as proposals in the thread, and nothing changes until you press Apply. If the subtitles change while a proposal waits, Ask again makes the agent read them and propose again. See [Proposals](/en/docs/ai/agent#proposals).
- **Skills:** the agent reads skills, instructions for kinds of work, when your request matches one: three come with HikariSub, and you and a Project can add your own in the Agent Skills format. Claude Code, Codex and ACP threads see them too, and **File › Settings › AI › Skills** lists which ones a window's threads get. See [Skills](/en/docs/ai/skills).
- **Project instructions:** Hikari AI reads your `AGENTS.md` from the user folder, then the Project's, in every kind of thread, and a bar says when a Project's `AGENTS.md` is on. The thread list puts the current Project's threads first. See [AGENTS.md instructions](/en/docs/ai/agent#agentsmd-instructions).
- **The agent reads and writes your Project's files:** in a window with a Project, a thread can list and read the Project's files, and every change it writes waits for your **Keep** in the Review panel. Credentials, `.env` and key files, the `.git` folder and the paths in `[ai] exclude` never reach it. See [What is sent](/en/docs/help/what-is-sent#ai).
- **Sub-agents:** the agent can split work across up to 4 sub-agents per thread, on any provider. Each one edits only its own lines, every change waits in the review, and it never runs in a broader mode than its parent. See [Sub-agents](/en/docs/ai/agent#sub-agents).
- **Long conversations:** at 90% of the model's context window, the Agent panel clears old tool results and then summarises older turns, and `/compact` or **Compact conversation** does it by hand. The full history stays visible in the panel. See [Long conversations](/en/docs/ai/agent#long-conversations).
- **MCP servers for the agent:** **File › Settings › AI › MCP servers** adds a local command or a streamable-HTTP URL whose tools the agent can use. A tool that only reads runs without asking, one that may destroy something asks in every mode, and the others ask as any change does. See [MCP servers](/en/docs/ai/agent#mcp-servers).
- **Web search in the Agent panel:** with **Let AI search the web** on, a globe beside **Attach** turns web search on or off for each thread. Answers that searched show numbered citations and a **Sources** list. See [Searching the web](/en/docs/ai/agent#searching-the-web).
- **AI inline actions:** **AI** in the Grid's and the Line editor's right-click menus runs one task on the lines you choose, with no Agent panel thread: **Rewrite…**, **Shorten to 15 CPS**, **Fix spelling and grammar**, **Translate to** and your own actions. Only the text changes, and override tags stay where they are. See [Inline actions](/en/docs/ai/inline-actions).
- **Lua scripts from the agent:** the agent can write a Lua Automation script and run it as a macro, and every run asks first, in every mode, Full access included. An approved script runs as one undo step and is saved in `ai/scripts` in your user folder. See [Lua scripts](/en/docs/ai/agent#lua-scripts).
- **Agents can write plugins:** a thread can write a plugin and ask to install it, and every install asks, in every mode, with the plugin's trust tier, signing, permissions, commands and code on the card. Running a plugin's command always asks too. See [Plugins](/en/docs/ai/agent#plugins).
- **Hikari AI times karaoke:** the agent splits lines into syllables, snaps and times them and runs the Kanji timer, then previews a karaoke template and applies it as one change that waits in the review. It can run WhisperX or the Montreal Forced Aligner if you've installed one, and asks every time. See [Timing karaoke](/en/docs/ai/agent#timing-karaoke).
- **The agent typesets signs:** it reads a sign's corners from the frame while HikariSub's own Perspective, clip, drawing, Position shifter and Hydra tools write the tags. Every line is checked against the sign before it reaches your review, and if one misses, nothing is applied. See [Typesetting signs](/en/docs/ai/agent#typesetting-signs).
- **The agent builds node effects:** agents can read, build and change node-effects graphs, preview the lines a graph would write, then save or apply it as one undo step. A graph with a Lua node runs only from node effects, never through the agent. See [Building node effects](/en/docs/ai/agent#building-node-effects).
- **The agent sets keyframes and lists macros:** agents can replace the video's keyframes, which asks as their other changes do, and list the Automation macros you loaded, but can't run them. See [Keyframes and macros](/en/docs/ai/agent#keyframes-and-macros).
- **Undoing a whole AI change asks first:** in the Review panel, **Undo** on a change asks before it drops lines you edited after the AI, and says how many. See [Keep and Undo](/en/docs/ai/review#keep-and-undo).
- **AI components, agent updates and provider ids in Settings:** **File › Settings › AI › AI components** shows the AI component's version, with **Check now** and **Update now**, and **External agents** shows whether Claude Code or Codex has an update. A provider's form shows the **Id** a Project's models and keys use. See [AI settings](/en/docs/ai/settings).
- **AI can't read your privacy settings or recent files:** the Agent panel, AI features and agents connected through MCP no longer see your recent files and Projects, or your privacy settings. See [What is sent](/en/docs/help/what-is-sent#ai).

### Node effects

- **Node effects:** build karaoke effects as a graph of nodes on a canvas, in a mode of its own: **View › Node effects**, or the button next to the layout switcher. The current line previews on the video after every edit, nothing is written until **Apply**, and all ten presets come as graphs. See [Node effects](/en/docs/karaoke/node-effects).
- **Typesetting graphs:** node effects run on ordinary lines too: select lines, choose **Subtitles › Typesetting graph…**, and pick one of ten ready-made graphs, such as Shake, Typewriter or Chromatic aberration. The new lines go after each original, which is kept as a comment. See [Typesetting graphs](/en/docs/karaoke/node-effects#typesetting-graphs).
- **Export as template lines:** the graph menu's **Export as template lines** writes template lines that make the same lines in a karaoke templater, as karaOK or Aegisub 3.2.2 templates. A graph that uses something a template can't express isn't exported, and a popup lists each node that blocks it. See [Exporting as template lines](/en/docs/karaoke/node-effects#exporting-as-template-lines).
- **Text to drawing and Combine drawings:** **Text to drawing** turns a syllable or line into a vector drawing in its style's font, and **Combine drawings** unites, subtracts, intersects or excludes two drawings. Each comes with an example under **From a preset**. See [Text and drawings](/en/docs/karaoke/node-effects#text-and-drawings).
- **Highlights and Inline-fx:** the Highlights node gives each syllable once per highlight, like the templater's `multi`, and the Inline-fx node keeps the units marked `{\-name}`, like `fx`. Both export as template lines. See [Highlights and inline-fx](/en/docs/karaoke/node-effects#highlights-and-inline-fx).
- **Audio peaks:** the Audio peaks node gives the audio's level over each syllable or span, so effects can follow the music. See [Audio peaks](/en/docs/karaoke/node-effects#audio-peaks).
- **Strips, copies and particles:** Clip gradient cuts units into coloured strips, Array copies each unit on a grid, a circle or a path, and Particles spreads copies at random, the same on every run. See [Strips, copies and particles](/en/docs/karaoke/node-effects#strips-copies-and-particles).

### Automation and native tools

- **The automation folder is reset once:** HikariSub 0.1.0-beta.4 moves your old `automation` and `config` folders to `automation-backup-<date>` in your user folder, because built-in versions now replace the karaoke templater and several scripts; nothing is deleted. A popup lists what moved and can reinstall the scripts DependencyControl had installed. See [The automation folder reset](/en/docs/automation/user-folder#the-automation-folder-reset).
- **The karaoke templater is built in:** HikariSub runs Karaoke Templater natively, and the lines it makes are the same as before. Its macros keep their names and keys, and named line templates now always run in the same order. See [Named line templates](/en/docs/karaoke/templater#named-line-templates).
- **karaOK templates:** the templater also runs templates written for karaOK, and the Template editor shows and switches a file's **Template language**. The lines are karaOK's, byte for byte, apart from fixes to karaOK's own bugs. See [karaOK templates](/en/docs/karaoke/templater#karaok-templates).
- **karaOK presets:** the Template editor's **From a preset** has ten more presets in karaOK's template language, such as Word pop, Furigana rise and Thai fade. See [Presets](/en/docs/karaoke/presets#karaok-presets).
- **ln.kara:** HikariSub comes with `ln.kara`, karaOK's template library, by logarithm with petzku, with eight of upstream's bugs fixed. The Template editor offers `ln.` and its functions as you type. See [The ln.kara library](/en/docs/karaoke/templater#the-lnkara-library).
- **Motion tracking, built in:** **Video › Tracking** does what Aegisub-Motion does: **Apply motion data…** moves the selected lines with After Effects keyframe data from Mocha or Blender, and **Revert motion data** puts them back. The Aegisub-Motion script still comes with HikariSub. See [Motion tracking](/en/docs/typesetting/motion-tracking).
- **Perspective tracking:** **Video › Tracking › Perspective tracking…** applies After Effects Power-Pin tracking data to the selected lines frame by frame. See [Perspective tracking](/en/docs/typesetting/perspective#perspective-tracking).
- **Track colour and Find fade:** **Video › Track colour…** follows a point's colour or alpha across the selected lines' frames and writes `\t` tags, and **Video › Find fade…** writes a `\fad` from where the sign fades in and out. See [Tracking a colour](/en/docs/typesetting/motion-tracking#tracking-a-colour).
- **Gradient visual tool:** a thirteenth visual tool, on <kbd>W</kbd>, makes gradients natively: in strips, across a clip, as a mask, by character or by line. **Apply gradient (Enter)** writes it as one step. See [Gradients](/en/docs/typesetting/visual-tools#gradients).
- **Text on path:** a fourteenth visual tool lays a line's text out along a path from its vector clip or one you draw, one line for each letter. **Apply** writes the new lines as one step and keeps the original as a comment. See [Text on path](/en/docs/typesetting/visual-tools#text-on-path).
- **Pathfinder and Offset for drawings:** Vector drawing's **Pathfinder** unites, subtracts, intersects or excludes the drawing with the line's clip or other picked lines, and **Offset** grows or shrinks it. The bundled `Yutils` runs its shape functions natively, with the same results. See [Combining and offsetting drawings](/en/docs/typesetting/visual-tools#combining-and-offsetting-drawings).
- **Blur and glow layers:** **Subtitles › Blur and glow layers…** builds glow, separate-border and stacked 3D-shadow layers under the selected lines, natively. The preview shows on the video, and building is one undo step. See [Blur and glow layers](/en/docs/typesetting/visual-tools#blur-and-glow-layers).
- **Remove tags:** **Remove tags…** removes the tag families you choose from the selected lines or the whole file, and can also clean up as the Clean Tags script does. A preview shows the result, and applying it is one undo step. See [Removing tags](/en/docs/basics/grid#removing-tags).
- **Interpolate across lines:** the Grid's **Interpolate across lines…** fills the lines between the first and last of three or more with the tag values between theirs. The video shows the result while the window is open. See [Interpolating across lines](/en/docs/basics/grid#interpolating-across-lines).
- **Position and alignment commands:** the Grid's menu has **Change alignment, keep position ›**, **Align and distribute ›**, **Position to margins** and **Margins to position**, and **Cycle** commands step `\blur`, `\bord`, `\shad`, `\alpha`, `\an` and `\fsp` through a list. None has a key at first. See [Position and alignment](/en/docs/basics/grid#position-and-alignment).
- **Line breaks, case and dialogue alternatives:** **Line breaks ›**, **Change case ›** and **Swap dialogue alternatives** are in the Grid's and the Line editor's text menus. They leave tags alone and are one undo step. See [Line breaks, case and dialogue alternatives](/en/docs/basics/grid#line-breaks-case-and-dialogue-alternatives).
- **Scripts written for Aegisub:** scripts get Aegisub 3.5.1's Lua API with the additions of arch1t3cht's fork, and Aegisub scripts run unchanged, DependencyControl ones included. See [Scripts written for Aegisub](/en/docs/automation/running-scripts#scripts-written-for-aegisub).
- **ILL's scripts load:** ILL's scripts and the scripts built on it, such as phos.RemoveTags and autoclip, now load on Linux and Windows, with the native Clipper2 library HikariSub ships. Install ILL itself as before. See [Scripts written for Aegisub](/en/docs/automation/running-scripts#scripts-written-for-aegisub).
- **Macros on big files:** macros run on subtitle files of up to about 64 MB, where before they stopped at about 8 MB, and their edits go in much faster on big files. See [Running a macro](/en/docs/automation/running-scripts#running-a-macro).
- **Faster karaskel and aegisub.util:** scripts that use `karaskel` or `aegisub.util`'s colour and text helpers run faster, with the same results. See [Modules](/en/docs/automation/writing-scripts#modules).

### Editing

- **One Find panel:** Find, Replace and In files are now one **Find** panel, with the replace row behind **▸**, the options behind **Options**, and **Search in** for this document, the open documents or a **Folder**. A count shows *3 of 12* as you type, and **Edit › Find previous** (<kbd>Shift</kbd>+<kbd>F3</kbd>) goes back. See [Find and replace](/en/docs/basics/find-and-replace).
- **Line editor additions from Aegisub 3.5:** **Edit › Insert hard space** puts `\h` at the cursor, <kbd>Shift</kbd>+<kbd>Enter</kbd> can put in `\n`, and time fields go up to 99:59:59.99. As the Line editor gets narrower, its fields wrap onto more rows and every field stays visible. See [The Line editor](/en/docs/basics/line-editor#the-text).
- **Line groups inside line groups:** **Make line group** on lines inside a group makes a group within it, and each level opens and closes on its own. A file with folds from arch1t3cht's Aegisub offers **Convert to line groups**. See [Groups inside groups](/en/docs/basics/grid#groups-inside-groups) and [Aegisub folds](/en/docs/basics/grid#aegisub-folds).
- **More splits, and overlapping lines:** **Split ›** has **At tag blocks** and **Every N frames or seconds…**, and splits keep a rotated sign in place. **Edit › Select lines** has **Overlapping lines**. See [Joining and splitting](/en/docs/basics/grid#joining-and-splitting).
- **Split into frames bakes animations:** each frame's line gets the values its `\t`, `\fad` and `\move` tags have reached on that frame. **Split › Bake animations** turns this off. See [Baking animations](/en/docs/basics/grid#baking-animations).
- **Sort lines by text:** **Edit › Sort all lines** and **Sort selected lines** have **Text** and **Text without tags**. See [Sorting](/en/docs/basics/grid#sorting).
- **Border type and text direction in styles:** the Style manager's **Opaque box** check box is now a **Border type** choice, with **Opaque box per line (libass)**, and **Text encoding** has **-1 - Detect text direction (libass)** for Arabic and Hebrew. Scripts read and write `borderstyle` as 1, 3 or 4, as in Aegisub. See [Editing a style](/en/docs/basics/styles#editing-a-style).
- **Search the font boxes as you type:** the Style manager's **Family** and **File › Settings › Appearance › Program font** filter your fonts as you type, and you can type in them again on Linux. See [Editing a style](/en/docs/basics/styles#editing-a-style).
- **Font collector asks before replacing fonts** in a folder that already has some of them: **Replace**, **Keep existing** or **Cancel**. See [Copying and zipping](/en/docs/typesetting/fonts#copying-and-zipping).
- **Resampling keeps 3D-rotated signs in shape:** **Subtitles › Resample subtitles** has **Adjust 3D rotations**, on by default, and no longer overwrites `LayoutResX` and `LayoutResY`. See [Resolution](/en/docs/basics/files-and-formats#resolution).
- **Credits written on save:** each save but an autosave can write the credits you choose into the ASS file's script properties, set in **File › Settings › Script properties › Credits**, with **Ask before changing them on save**. A Project can set them for everyone who opens it. See [Filling in the credits on save](/en/docs/basics/files-and-formats#filling-in-the-credits-on-save).
- **More is saved with your subtitles:** the Perspective tool's surrounding plane, which karaoke line each templated line came from, the order of runs in Translation mode, and the Kanji timer's skips. They survive reopening the file and a trip through Aegisub 3.4 or later. See [The surrounding plane](/en/docs/typesetting/perspective#the-surrounding-plane).
- **Typing applies itself in the Karaoke layout:** the Line editor applies your text 300 ms after you stop typing, and each burst of typing is one undo step. See [Typing applies itself](/en/docs/customize/layouts#typing-applies-itself).
- **Save as converts to ASS:** **Subtitles › Conversion** is gone; choose ASS in **File › Save as…**, and HikariSub lists what will change and asks first. Keys you gave the old convert commands are removed, with a notice. See [Saving as ASS](/en/docs/basics/files-and-formats#saving-as-ass).
- **File › Export as… writes a copy in another format:** SubRip (SRT), WebVTT, YouTube SBV, plain text, MicroDVD, MPL2, TMPlayer, **TTML (IMSC1)** or **DFXP**, and the file you are editing stays as it is. A report lists each line that lost something the format can't carry. See [Export](/en/docs/basics/export).
- **YouTube timed text (srv3):** **File › Export as…** writes srv3 (`.ytt`) exactly as YTSubConverter 1.6.5 does, and **File › Open…** opens `.ytt` and `.srv3` files as a new ASS file. See [YouTube timed text (srv3)](/en/docs/basics/export#youtube-timed-text-srv3).
- **Import lyrics:** **File › Import lyrics…** turns LRC, TTML and decoded Kugou KRC and QQ Music QRC files into lines, word-timed with `\k`. HikariSub doesn't decrypt KRC or QRC files. See [Importing lyrics](/en/docs/basics/files-and-formats#importing-lyrics).
- **QC notes:** **Subtitles › QC notes…** opens a panel for the notes of a QC pass, kept in the subtitle file itself, where Aegisub keeps them too. It imports arch1t3cht's Note Browser and mpvQC notes, and exports Note Browser's. See [QC notes](/en/docs/checking/qc-notes).

### Timing and audio

- **Shift times and the Timing postprocessor are two panels**, from **Subtitles › Shift times…** and **Subtitles › Timing postprocessor…**, each with its own presets and a preview of the lines it would change. Your Shift times profiles became presets. See [Shift times](/en/docs/basics/timing#shift-times).
- **Timing helpers and the timing assistant:** **Subtitles › Timing helpers** snaps to keyframes, adds or removes lead-in and lead-out, moves by one frame and extends neighbours. The Timing postprocessor's **Assistant** tab goes through the lines and suggests times, saying why. See [Timing helpers](/en/docs/basics/timing#timing-helpers) and [The assistant](/en/docs/basics/timing#the-assistant).
- **Audio display from Aegisub 3.5:** the paused video's frame and the one before it are shaded on the audio display, and **Snap to keyframes** also snaps to the middle of either frame. **Go to selection start** and **Go to selection end** are in the Audio panel's **»** menu. See [The Audio panel](/en/docs/basics/audio#what-the-display-shows).
- **Video › Shift by frames to video:** four commands move lines by whole frames, so that the active line starts or ends on the frame on screen. See [From the video](/en/docs/basics/timing#from-the-video).
- **Video › Centre times within frames** moves the selected lines' starts and ends to the middle of their frames. See [Centring times within frames](/en/docs/basics/timing#centring-times-within-frames).
- **Audio › Join with previous line using the audio selection** gives the active line the audio selection and ends the line before it there, in one undo step. See [From the audio](/en/docs/basics/timing#from-the-audio).
- **Insert start time and Insert end time from video keep a joined neighbour joined:** a line that ended where the selected line started, or started where it ended, moves with it.
- **Play in mono:** **File › Settings › Audio › Playback › Play in mono** mixes the Audio panel's playback down to one channel. See [Settings](/en/docs/basics/audio#settings).

### Video

- **WebM, VP8, VP9 and AV1:** WebM videos open, with VP8, VP9 or AV1 video and Vorbis or Opus sound. AV1 plays only with a hardware AV1 decoder; without one, its frames still show while paused. See [Formats](/en/docs/basics/video#formats).
- **Zoom and pan the video as in Aegisub 3.5:** <kbd>Ctrl</kbd>+wheel zooms around the pointer, <kbd>Shift</kbd>+wheel and a middle-button drag pan, and the plain wheel no longer zooms by default. **File › Settings › Video › View › Zoom and pan** brings back HikariSub legacy's crop zoom. See [Zoom and pan](/en/docs/basics/video#zoom-and-pan).
- **Timecodes files:** **Video › Open timecodes** loads a v1, v2 or v4 file, and **Save timecodes** writes a v2 file. Each tab keeps its own, and an ASS file remembers it as in Aegisub. See [Timecodes](/en/docs/basics/video#timecodes).
- **Align to video:** **Video › Align to video…** times the active line to the frames where a point you click keeps its colour, as in Aegisub. See [Aligning to the video](/en/docs/basics/video#aligning-to-the-video).
- **Video from Aegisub 3.5:** opening a video asks to set the YCbCr matrix and layout resolution and warns about HDR or wide-gamut colours, and **Video › Video details…**, **Reload video**, **Reload audio** and subtitles-only frame export are new. Dummy video takes a fractional frame rate. See [Opening a video](/en/docs/basics/video#opening-a-video).
- **The video and audio backend loads when it's needed:** HikariSub starts without it and loads it the first time you open video or audio, so that first action can take about a second longer. See [Output device](/en/docs/basics/audio#output-device).

### Plugins

- **Plugins:** **Automation › Plugins…** installs plugins from `.hikariplugin` files, shows what each asks for and who signed it, and turns them on or off. A plugin's commands sit in the Automation menu, and it can add panels and dialogs. See [Using plugins](/en/docs/plugins/using-plugins).
- **The plugin marketplace:** the plugin manager's **Marketplace** view lists plugins from the HikariSub marketplace, with search and categories, and installs them after the usual question. **Install in HikariSub** on the marketplace website opens HikariSub at that plugin. See [From the marketplace](/en/docs/plugins/using-plugins#from-the-marketplace).
- **HikariSub's own plugins:** [Macro chains](/en/docs/plugins/using-plugins#macro-chains) records commands and Automation macros as a chain and runs it again as one undo step. [Keyframe generator](/en/docs/plugins/using-plugins#keyframe-generator) finds the scene changes in the open video as a background job you can cancel, then sets them as the video's keyframes or saves an Aegisub keyframes file, and [Git line marks](/en/docs/plugins/using-plugins#git-line-marks) marks the lines added, changed or removed since a git branch, tag or commit.
- **By HikariSub:** the Plugins window and the marketplace website mark HikariSub's own plugins **By HikariSub**, an icon in the list and a badge beside the name. Only plugins under the hikarisub handle signed with HikariSub's author key get it.
- **Plugins update themselves:** marketplace plugins install new versions on their own, and an update that asks for more access waits for **Review…**. **Roll back to** returns to the version before. See [Keeping plugins up to date](/en/docs/plugins/using-plugins#keeping-plugins-up-to-date).
- **Plugins run in a sandbox:** on Linux and Windows, ordinary plugins run in an operating-system sandbox, where they reach only their own package and have no network of their own. Full trust plugins run outside it. See [Safety and limits](/en/docs/plugins/using-plugins#safety-and-limits).
- **Plugin folders and the internet:** a plugin asks before it uses a folder, and **File › Settings › Updates and privacy › Let plugins connect to the internet** turns off every plugin's connections at once. See [Folders and files](/en/docs/plugins/using-plugins#folders-and-files).
- **Plugins can draw their own panels:** a plugin with full trust can draw a panel itself, in QML, that docks like any other. See [Plugin panels](/en/docs/plugins/using-plugins#plugin-panels).
- **What plugins can do:** a plugin can run long jobs with a progress card and **Cancel**, group its steps into one undo step, mark Grid rows, run your Automation macros, replace the video's keyframes, read video frames and colours, and, with `vcs.read`, read the git repository holding your subtitle files. See [Long jobs](/en/docs/plugins/write-your-first-plugin#long-jobs) and [Git](/en/docs/plugins/write-your-first-plugin#git).
- **Plugins and Projects:** a plugin can read and write the folder of the Project you work in, once you trust that folder, through the new `project` place. See [Folders and files](/en/docs/plugins/using-plugins#folders-and-files).
- **Plugins can add node-effects nodes:** a plugin lists its nodes in its manifest, and they show in **Add node** under the plugin's name. See [Nodes from plugins](/en/docs/karaoke/node-effects#nodes-from-plugins).
- **A guide for plugin authors, and the API reference:** [Write your first plugin](/en/docs/plugins/write-your-first-plugin) builds a plugin in three steps, and the [Hikari API reference](/en/docs/plugins/api-reference) lists every operation, event and type.

## 0.1.0-beta.3

Published 2026-10-31. [Release notes](https://github.com/altqx/hikari/releases/tag/v0.1.0-beta.3)

<Callout type="warn" title="Security fix: please update">
  0.1.0-beta.1 and 0.1.0-beta.2 have a security issue in how scripts are loaded. In them, a subtitle file can make HikariSub load and run the Automation scripts it names without asking, and a file in your `include` folder can replace HikariSub's own Lua modules. 0.1.0-beta.3 fixes it, so update if you use an earlier beta. The advisory, [GHSA-g2j7-9r6j-r28v](https://github.com/altqx/hikari/security/advisories/GHSA-g2j7-9r6j-r28v), has the details.
</Callout>

### Security

- **Scripts a subtitle file names ask before they load.** The question shows each script's full path. You can load them, not load them, or always trust their folder. See [Running scripts](/en/docs/automation/running-scripts#scripts-a-subtitle-file-names).
- **HikariSub's own Lua modules always load from the copy that ships with it**, so a file of the same name elsewhere can't replace them. See [Modules](/en/docs/automation/writing-scripts#modules).

### Fixed

- **No more freeze on the first start on Windows.** Getting started mistook HikariSub's own bundled dictionaries for old settings to import, and copied them while the window waited.
- **Saving on Windows no longer fails when another program is reading the file.** A virus scanner, the search indexer or a preview could briefly block the save. HikariSub now retries for up to 3 seconds. If the save still fails, it says the file on disk is unchanged. See [Saving](/en/docs/basics/files-and-formats#saving).
- **Audio keeps playing when its output device goes away.** Playback moves to the system default instead of going silent. See [Output device](/en/docs/basics/audio#output-device).
- **Screen readers read a panel's ⋯ menu in the order it is drawn.** The panel's own items used to be read after Move panel…, Undock and Close.
- **Crash reports from Linux builds have symbols again**, so crashes can be traced to a line.

### New and improved

- **A splash on Windows while HikariSub starts**, with the "Hikari sunrise" artwork in light and dark. See [Install](/en/docs/get-started/install#starting-hikarisub).
- **Full screen bar in the video's right-click menu:** Auto, Always or Never, from the Video panel or in full screen. See [Full screen](/en/docs/basics/video#full-screen).
- **More icons** in menus and toolbars, so commands that shared one icon now have their own.
