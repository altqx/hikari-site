HikariSub works on ASS subtitles, and opens and saves the common simpler formats too. Each file opens in a tab of its own.

## Opening

**File › Open…** (<kbd>Ctrl</kbd>+<kbd>O</kbd>) opens a subtitle file. The picker opens in the folder you last used and lists:

- **Subtitles:** ASS, SSA, SRT, SUB, TXT and MPL files.
- **Word-timed lyrics:** LRC and TTML files, which open as a new ASS file named after them.
- **YouTube timed text:** `.ytt` and `.srv3` files, which open as a new ASS file too. See [Opening srv3 files](/en/docs/basics/export#opening-srv3-files).
- **Videos with embedded subtitles:** an MKV file's subtitle track opens as subtitles, also one stored compressed. **File › Import subtitles from MKV…** does the same.

HikariSub reads what the file holds rather than trusting its name. A `.txt` or `.sub` file can be MicroDVD (`{1}{25}text`, timed in frames), MPL2 (`[10][25]text`), TMPlayer (`0:00:01:text`, start times only) or plain text without times. A file that turns out to be ASS or SRT opens as that.

**File › Recently opened subtitles** lists the last 20 files. <kbd>Ctrl</kbd>+click one to show it in its folder instead. The Home page lists them too.

If the file can't be opened, nothing changes: the tab keeps what it had, and the Log says why.

<Callout type="warn">
  Subtitles must be UTF-8. Convert a UTF-16 or legacy-charset file to UTF-8 in a text editor before you open it.
</Callout>

When the subtitles name a video, audio or keyframes file, a bar offers to load them. If the video's size differs from the subtitles' resolution, HikariSub asks whether to [resample](#resolution) them.

## Saving

| Command | Key |
| --- | --- |
| **File › Save** | <kbd>Ctrl</kbd>+<kbd>S</kbd> |
| **File › Save as…** | <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>S</kbd> |
| **File › Save all** | |

A file is saved in the format it is in: an SRT file stays SRT. Save asks for a name when the file is new, and when **Save subtitles using the video name** is on and the names differ. The right extension is added if the name lacks it.

Only what you changed is rewritten. Everything else, including sections and lines other programs added, is saved exactly as it was. The file is written beside the old one first and then put in its place, so a failed save never leaves half a file.

On Windows, another program reading the file, such as a virus scanner, the search indexer or a preview, can briefly stop HikariSub from putting the new file in place. From 0.1.0-beta.3, HikariSub keeps trying for up to 3 seconds.

When a save fails, an error notice and the status bar say **Save failed; the file on disk is unchanged**. The file keeps its last saved version, and your changes stay unsaved in HikariSub. Close the program that has the file open, or wait a moment, and save again. The notice's entry in the [Log](/en/docs/help/troubleshooting#the-log-panel) gives the file's full path.

If the file changed on disk since you opened it, Save stops and a bar offers to **Reload** it, **Compare** the two, or **Keep mine**. A read-only file offers **Save as…** instead.

**Edit › Undo to last save** goes back to the saved version, and **Edit › History** (<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>H</kbd>) to any step before or after it.

ASS files also keep the tab's arrangement of panels in a `[Hikari]` section that other programs ignore. Opening the file again brings the panels back the way you left them. To leave it out, turn off **File › Settings › Script properties › Save the panel layout in subtitle files**.

## Saving as ASS

To turn an SRT, WebVTT, SBV, MicroDVD, MPL2 or TMPlayer file into ASS, use **File › Save as…**. For a file in another format, the save window offers its own format and **ASS subtitles (\*.ass)**. A name ending in `.ass` chooses ASS too.

Choosing ASS asks first: *Convert "episode-01.srt" to ASS before saving it?*, with a list of what changes, such as lines given the conversion style, tags converted, times changed, and duplicate or empty lines removed.

- **Convert to ASS** converts the file in one undo step, *Subtitles conversion*, and saves it. The same list goes to the [Log](/en/docs/help/troubleshooting#the-log-panel).
- **Cancel** leaves the file as it was and saves nothing.

Closing a tab with unsaved changes asks the same way when you save it as ASS there.

**File › Settings › Conversion** sets how a file is converted: the style every line gets, from a catalogue, tags to put at the start of every line, the resolution, the frame rate for a MicroDVD file (or **From video**), and new end times from each line's length.

To write a copy in another format and leave the file as it is, use [Export](/en/docs/basics/export).

- **Credits:** the title, and who wrote, translated, checked, timed and edited it.
- **Resolution:** the size the lines are written for, and the layout size. **From video** takes the open video's. **YCbCr matrix** tells players which colours the video uses, so that subtitle colours match it.
- **Rendering:** how long lines wrap, which way colliding lines stack, and whether borders and shadows scale with the video.

**Save** writes only what you changed, as one undo step.

## Resolution

A subtitle file's positions, sizes and margins are written for its resolution. **Subtitles › Resample subtitles** scales all of them to another one, for example when the subtitles were made for a 1280 × 720 video and the release is 1920 × 1080.

Set **Target**, or take it **From video**. When the aspect ratio changes, choose to **Keep it**, or **Stretch** the lines to the new shape: text and drawings grow wider when the width grew more, and taller when the height did. **Resample** scales the styles' sizes, outlines, shadows and margins, the lines' margins, and position, clip, border, shadow and size tags and drawings, in one undo step.

**Adjust 3D rotations**, ticked at first, keeps lines turned in 3D with `\frx` or `\fry` looking the same on screen, as arch1t3cht's Resample Perspective script does. HikariSub works out each such line's corners on the new frame, then sets its position, origin, rotations, shearing, scaling, outline and shadow again to match them. When the aspect ratio changes, this also covers lines turned about their own `\org`, and with **Stretch**, any turned or sheared line. Lines that look the same after plain scaling keep their tags. Lines that move with `\move`, change shape over time or can't be measured are only scaled, and one notice in the [Log panel](/en/docs/help/troubleshooting#the-log-panel) lists them by line number.

Resampling keeps the file's `LayoutResY`, and changes `LayoutResX` by as much as the aspect ratio changes, when the file has both.

When you open a video of another size, the same choice comes up: **Resample**, which adjusts 3D rotations too, **Change resolution only**, which sets the new size without scaling anything and leaves `LayoutResX` and `LayoutResY` alone, or **Keep as is**.

## Tabs

Each open file has its own tab in the row under the menu bar, with its own video, audio and undo history.

| Key | Does |
| --- | --- |
| <kbd>Ctrl</kbd>+<kbd>T</kbd> | New tab |
| <kbd>Ctrl</kbd>+<kbd>W</kbd> | Close the tab |
| <kbd>Ctrl</kbd>+<kbd>PgDn</kbd> <kbd>Ctrl</kbd>+<kbd>PgUp</kbd> | Next or previous tab |

Drag a tab to move it, and middle-click it to close it. A dot marks a tab with unsaved changes. Closing the last tab shows the Home page.

Right-click a tab, or press <kbd>Menu</kbd> or <kbd>Shift</kbd>+<kbd>F10</kbd> on it, for its menu:

- **Save** and **Save all**.
- **Show in folder** and **Copy path**. When the tab also has a video, audio or keyframes, each has a row for every file.
- **Subtitle comparison ›** and **Switch to ›**, which lists the open tabs.
- **Move tab to new window** and **Move tab to window ›**. See [Windows](/en/docs/customize/layouts#windows).
- **Close**, **Close other tabs**, **Close tabs to the right** and **Close all tabs**. Each asks about unsaved changes first.

Right-click the empty part of the tab row for **New tab**, **Save all**, **Switch to ›** and **Close all tabs**. <kbd>Tab</kbd> reaches the current tab, and <kbd>Left</kbd> and <kbd>Right</kbd> move between tabs.

A file opens in the current tab when the tab is empty and unchanged. **File › Settings › General › Tabs › Always open subtitles in a new tab** gives every file a tab of its own. Files opened from your file manager, or while HikariSub is already running, always get a new tab.

**File › Remove subtitles from the editor** empties the tab, after asking about unsaved changes.

## Projects

A Project is a folder you open in a window, such as the folder of a whole show or of one episode. Each window can have one Project. Its name shows in the title bar, as in *Episode 01.ass - My Show - HikariSub*, and on the window's Home page. The window's tabs can still hold files from outside the folder. HikariSub writes nothing into the folder.

### Opening a folder

- **File › Open folder…**, or **Open folder…** on the Home page.
- **Drop a folder** on the window, on its own.
- **From a terminal,** `hikarisub <folder>`. See [Command line](/en/docs/reference/command-line#folders).

A folder opens in the current window when that window has no Project and nothing open, or only one empty, unchanged tab. Otherwise it opens in a new window. A folder that is already open in a window brings that window to the front: one Project can't be open in two windows.

Once you have opened a Project, the Home page lists **Recent projects** above **Recent files**, the last 20, and you can filter them by name. Right-click one for **Open**, **Show in folder**, **Copy path**, **Remove from list** and **Remove missing folders**.

### A file in a Project folder

When you open a subtitle file in a window with no Project, HikariSub looks for a folder named `.hikari` beside the file, then in each folder above it. The first folder holding one is the file's Project:

- If it is in one of your trusted folders, listed in **File › Settings › Automation › Trusted script folders**, it opens as the window's Project at once.
- Otherwise a bar says *This file is in the project My Show.*, with **Open project**, which opens it in this window.

Nothing is offered when that Project is already open in another window.

### Closing a Project

**File › Close project** closes the window's tabs, after asking about unsaved changes, and leaves the window on the Home page without a Project. It is greyed out in a window with no Project.

HikariSub keeps the tabs a Project had when you closed it, or when you closed its window. The next time the Project is open in a window with no tabs, its card on the Home page lists them, with **Reopen last tabs (3)**.

**Open folder…** and **Close project** have no shortcut at first. Give them one in **File › Settings › Shortcuts**.

## Autosave and recovery

HikariSub keeps copies of changed files as you work, 20 seconds after a change. If it closes without warning, the Home page says so the next time and offers them.

**File › Open autosave…** lists the copies by file and time. **Open copy** opens one as a new, unsaved file, named "(recovered)": your original file is not touched. **Delete older than…** clears old ones. The autosaves of HikariSub 0.0.x are listed too, read only: see [Moving from legacy](/en/docs/get-started/moving-from-legacy#what-does-not).

**File › Settings › General › Saving › Autosave files kept** sets how many copies of each file are kept, from 2 to 1000000, 3 at first. Copies older than 30 days are deleted, and so are a file's copies once you save and close it.

## Sessions

A session is the set of open tabs, with their videos, audio and positions. **File › Last session** can:

- **Load last session**, the tabs open when you last quit.
- **Load session from file** or **Save session to file**, as a `.hksession` file.
- Ask whether to load the last session when HikariSub starts, or load it without asking.

If a file the session names has moved, a bar offers to **Retry**, **Relink…** it, or **Remove** it.

A session also keeps your windows. Loading one, at start, from **File › Last session** or a file, or after a crash, opens each window where it was, at its size and maximised or not, with its tabs in order and the same tab in front. A window last on a monitor you have since unplugged comes back on your main screen. On Wayland the desktop chooses where windows go, so only the size and whether it was maximised come back. Each window's [Project](#projects) comes back too, unless its folder is gone. See [Windows in a session](/en/docs/customize/layouts#windows-in-a-session).

**Load session from file** also opens `.kls` sessions from HikariSub 0.0.x, but HikariSub never writes one: a name you type ending in `.kls` is saved as `.hksession`. Opening a `.hksession` or `.kls` file from your file manager, or dropping one on the window on its own, loads it the same way.

A session file is JSON, with each tab's files and positions. Its paths are full paths, so a session made on one computer opens the same files only where they have the same paths.

### Files on another computer

When a session names files on a network share, such as `\\server\subs\ep01.ass`, HikariSub asks first: "This session opens files on another computer.", naming the computers. Nothing is contacted until you press **Open**, and **Open** reaches only the computers it named. **Cancel** loads nothing.

### The last session

The last session is kept in `last-session.json` in your [user folder](/en/docs/automation/user-folder). HikariSub versions before it kept `LastSession.txt`: the first start of a newer version converts it once and keeps it as `LastSession.txt.old`, and the offer to restore after a crash still works. If `last-session.json` can't be read, it is kept as `last-session.json.broken`, the Log names the file and line, and no tabs are restored.
