---
title: Node effects
description: Build karaoke effects as a graph of nodes on a canvas, preview them on the video line by line, and apply them to the file.
---

A node effect is a graph of nodes, wired together on a canvas, that turns karaoke lines into new lines. It does the job of [templates](/en/docs/karaoke/templater) without writing template syntax. Each node does one thing: picks the syllables, works out a time, writes a tag or outputs the lines.

A graph is saved in the file as a comment line whose Effect is `graph` and the graph's name. The lines it writes have the Effect `fx` and the same name. Like the templater's lines, they fold with [Fold generated lines](/en/docs/customize/layouts#karaoke-mode-and-folding). A file can hold several graphs, and applying one never touches another graph's lines or the templater's.

## The mode

Node effects are edited in a mode of their own. There are three ways in:

- **View › Node effects**;
- the node-effects button in the title bar, next to the layout switcher;
- a key you give it. It has none at first: [Shift+click](/en/docs/customize/hotkeys#shiftclick) **View › Node effects**, or find **Node effects** on the Shortcuts page.

The mode needs an open file, and it is greyed out while the [layout is locked](/en/docs/customize/layouts#locking-the-layout).

**Leave node effects**, at the end of the mode bar, brings back the tab's layout as you left it. It never asks anything. The same menu item, button and key also leave the mode.

The mode has its own layout. Video and **Source lines** are on the left, **Graph** is in the middle and **Node** is on the right. The Grid, the Line editor and the audio close while the mode is on. You can move these panels like any others, and the mode keeps your arrangement for the next time. **View › Layout › Reset this layout** puts the mode's own layout back.

## The mode bar

The mode bar picks the graph you work on, from the graphs in the file. Its menu has:

- **New graph**;
- **From a preset**, which adds one of the [presets](#presets);
- **From the library…**, which adds a graph from [your library](#the-library);
- **Rename…**;
- **Duplicate**;
- **Save to the library**;
- **Export as template lines**, which turns the graph into [template lines](#exporting-as-template-lines);
- **Delete graph**, which removes the graph and the lines it wrote. Undo brings them back.

A graph name can't be empty, start or end with a space, end with a dot, or hold `karaoke`. Two graphs in a file can't have the same name.

Also on the bar:

- **Style** picks the style of the karaoke lines the graph runs on, or **All styles**.
- **Seed** sets the graph's seed, which every Random node draws from. **New seed** picks another.
- The problem count, such as **2 problems**, opens the list of problems. Picking one selects its node and brings it into view.
- **Apply** writes the graph's lines for every karaoke line. The arrow next to it has **Apply to every karaoke line** and **Apply to the selected lines**, which regenerates only the lines selected in **Source lines**. The others keep their output.

## Panels

- **Graph** is the canvas. Its header has **Add node** and **Fit the graph in view**, and shows how many nodes and wires there are.
- **Node** shows the selected node:
  - what it does;
  - its **Name**, which is the node's id. You can rename it;
  - editors for its fields;
  - its wired inputs, each with **Disconnect**;
  - its values on the current source line, from the last run;
  - its timing;
  - its problems.
- **Source lines** lists the karaoke lines the graph runs on. The one you pick is the line the preview runs on.

## Wiring

A node has its inputs on the left and its outputs on the right. Drag from an output to an input to wire them.

- **Ports are typed.** Each type has its own shape and colour: Units are diamonds, Tags are squares and the other types are circles. Number, Time and Alpha share a colour, because they connect to one another. In a high-contrast theme, only the shapes differ.
- **Wrong wires are refused.** While you drag, the inputs the output can't feed are dimmed. Dropping on one is refused, with the reason, such as *A Text can't connect to a Number input.* A wire that would make a loop is refused too.
- **An input takes one wire.** Dropping on an input that is already wired replaces its wire. Drag a wire off an input to move it, or drop it on empty space to remove it.
- **Unwired inputs use their field.** Their port is hollow, with the value written in.
- **Dropping a wire on empty space** opens **Add node**, showing only the nodes that can take that output.

**Add node** also opens from the Graph header or a double-click on the canvas. It lists the nodes by category, with Lua last, and searches their names and what they do. **Recently added** at the top holds the nodes you added last.

To group nodes, select them and press <kbd>Ctrl</kbd>+<kbd>G</kbd>. A group is one node on the canvas, and you rename it like any other node. **Unit info**, which gives the current unit's values, shows only its wired outputs and folds the rest: **3 more outputs** unfolds them.

| Key | What it does |
| --- | --- |
| Arrows | Move the selection to the nearest node in that direction |
| <kbd>Ctrl</kbd>+arrows | Move the selected node |
| <kbd>Delete</kbd> | Delete the selected node |

Each node has an accessible name for screen readers, such as *Choose, palette: 1 of 1 inputs wired*. The Node panel lists every wire of the selected node.

## Preview and Apply

While the mode is on, the graph runs on the current source line after every edit. The video shows that line's output in place of its generated lines, with the badge *Preview · line 4 · not applied*. **Source lines** turns the preview on the video on and off, and can loop the line. When the graph has a problem, the preview keeps the last run that worked, dimmed.

Nothing is written to the file until you press **Apply**. Apply replaces the lines the graph wrote before, and marks each karaoke line it used as a comment with the Effect `karaoke`, as the templater does.

Each change on the canvas is part of one **Edit graph** step in the undo history. Changes made in quick succession, or one drag, are one step. **New graph**, **Rename…**, **Duplicate**, **Delete graph** and **Apply** are one step each.

## Characters

A `char` unit is a character as it is drawn, as in the templater's [Characters](/en/docs/karaoke/templater#characters). Thai vowel and tone marks stay on their letters, so `กินน้ำ` gives `กิ`, `น` and `น้ำ`. A letter with a combining accent, and an emoji made of several joined emoji, are one character too. Thai support is by Jibrill.

## Strips, copies and particles

Three nodes under **Units** in **Add node** give each unit, such as a line or a syllable, once for each strip, copy or particle, with its number and how many there are:

- **Clip gradient** cuts the unit's box into strips, side by side or stacked, with padding around the box if you want it. Each strip gives its own `\clip` rectangle and a colour from a gradient of `#RRGGBB` stops. The edges are whole pixels, and neighbouring strips share theirs, so the strips leave no gaps. To clip the strips to a drawing, intersect a drawing of each strip's rectangle with the shape in [Combine drawings](#text-and-drawings), and wire the result into a `\clip` tag.
- **Array** places copies around the unit: on a grid centred on it, on a circle around it, or evenly along a drawing wired into its path. Each copy gives its offset, its position and an angle in degrees, as `\frz` takes it. An Array on a path with no drawing wired in is a problem.
- **Particles** spreads copies at random over a rectangle or an ellipse centred on the unit. They draw from the graph's seed and the node's own seed, so the same graph seed, node seed and line give the same particles on every run, on Linux and Windows alike.

## Audio peaks

**Audio peaks**, under **Audio** in **Add node**, gives the level of the file's audio over each syllable, or over any span you give it in milliseconds, so an effect can follow the music. Its **level** output goes from 0 to 1 with the loudest sample. **low** and **high** give the lowest and highest samples, from -1 to 1.

With no audio open, or while the audio is still opening, Audio peaks gives 0, and the graph shows a problem at the node. As with any problem, Apply writes nothing, and the preview keeps the last run that worked. Opening another audio file runs the graph again.

## Highlights and inline-fx

Two nodes under **Units** in **Add node** work like the templater's `multi` and `fx` modifiers:

- **Highlights** gives each syllable once for each of its highlights, as `multi` does. A syllable whose text starts with `#`, as in `{\k20}空{\k20}#`, is another highlight of the syllable before it. For each highlight, the other nodes see that highlight's start, end and duration. A character has its syllable's highlights, and a furigana or line unit has one, its own. At first it leaves out highlights with no duration, as `multi noblank` does.
- **Inline-fx** keeps only the units marked with the inline-fx name you give it, as `fx` does. A `{\-name}` in a line marks the syllables from there to the next one. Characters have their syllable's inline-fx, and a line unit has none. With the name empty, it keeps the units with no inline-fx.

## Text and drawings

Two nodes under **Drawings** in **Add node** make vector drawings, which an **Emit** writes as its line's drawing:

- **Text to drawing** draws each unit's text, without its tags, in the font of its line's style: the font, size, bold, italic, underline, strike-out, scale and spacing. Wire a text into it to draw that instead. The drawing is at `\p1` and starts at the text's top left, as Yutils' `text_to_shape` gives it, so `\an7` and a `\pos` at the unit's left and top put it over the unit. Its **width** and **height** are the text's. It uses the fonts the video finds. When it can't read the style's font, it gives an empty drawing, and the graph shows a problem at the node, such as *can't read the Style's font "Missing", so it gives an empty drawing*.
- **Combine drawings** takes two drawings, **a** and **b**. It unites them (what either covers), subtracts **b** from **a**, intersects them (what both cover) or excludes them (what only one covers). Each drawing is filled as libass fills it and keeps its own `\p` scale. The result is at `\p1`.

## Presets

**From a preset** adds one of the ten [presets](/en/docs/karaoke/presets) as a graph, under the same name as in the Template editor:

- Classic fill;
- Staggered fade;
- Colour sweep;
- Scale pop;
- Bounce;
- Glow;
- Sparkles;
- Echo;
- Falling letters;
- Colour per line.

Each graph writes the same lines as its template, byte for byte, and none of them uses Lua. Colour sweep, Glow and Echo have two **Emit** nodes, one for each layer of the template.

After the presets come eight examples, one for each of the newer nodes: the [strips, copies and particles](#strips-copies-and-particles) nodes, [Audio peaks](#audio-peaks), [Highlights and Inline-fx](#highlights-and-inline-fx), and [Text to drawing and Combine drawings](#text-and-drawings):

- **Gradient strips**: each line cut into eight strips, coloured from pink to blue.
- **Ring of copies**: eight copies of each syllable on a circle around it, each turned to its place, while it is sung.
- **Particle burst**: twelve copies of each syllable fly out to random places around it and fade.
- **Audio pulse**: each syllable grows with how loud the audio is while it is sung. It needs audio open.
- **Highlight flashes**: an outline flashes on each syllable once for every highlight, as the templater's `multi` does.
- **Paint and cloud**: syllables marked `{\-paint}` fill from red to white, those marked `{\-cloud}` rise and blur, and the rest stay in place.
- **Text outlines**: each syllable is drawn as a hollow drawing in its style's font, and its outline thickens while it is sung.
- **Striped letters**: each syllable's letters are cut into thin horizontal stripes, which fade in as it is sung.

Highlight flashes and Paint and cloud also [export as template lines](#exporting-as-template-lines). The other six use nodes no template can express.

## The library

**Save to the library** keeps a copy of the graph in the `node-effects` folder of your [user folder](/en/docs/automation/user-folder#whats-in-it), one file per graph. **From the library…** adds one of them to the file you are working on, so you can reuse a graph in other files.

## Exporting as template lines

**Export as template lines** adds template lines after the graph line that make the same lines in the [karaoke templater](/en/docs/karaoke/templater), so the effect also runs in Aegisub. Its submenu has two formats:

- **karaOK templates**, marked with an (i), writes [karaOK](/en/docs/karaoke/templater#karaok-templates) templates and sets the file to karaOK. They run in HikariSub; in Aegisub they need the karaOK templater.
- **Aegisub 3.2.2 templates** writes templates that Aegisub's own templater runs.

The **Classic fill** preset, for example, becomes a `line` and an `lsyl` template as karaOK, or a `pre-line` and a `line` template for Aegisub 3.2.2. The menu ticks the format you used last, karaOK at first. The graph line stays, and the export, the karaOK line included, is one undo step, *Export as template lines*. All ten [presets](#presets) export.

Highlights exports as `multi`, and Inline-fx as `fx` and its name. An Inline-fx with an empty name exports as an `fxgroup`, which a code line sets for the units with no inline-fx.

A graph that uses something a template can't express isn't exported. That includes random numbers, among them the Particles node, Lua nodes, [nodes from plugins](#nodes-from-plugins), a condition on an Emit, the Clip gradient, Array, Audio peaks, Text to drawing and Combine drawings nodes, and Highlights on whole lines. A popup says *These nodes have no form in a karaoke template, so the graph can't be exported:* and lists each node that blocks it with the reason, such as **dice:** draws numbers the templater can't draw again. Choosing one selects it.

### karaOK files

Node effects follow the file's [template language](/en/docs/karaoke/template-editor#the-template-language). In a karaOK file, places are rounded to 0.1 px, and a syllable with no length isn't blank, so it still gets its lines, as in karaOK. In an Aegisub 3.2.2 file, places are whole pixels and such a syllable is blank.

## Lua nodes

The **Lua** node runs a short piece of Lua code once per line, for all its units. Its inputs are globals, and the code sets its outputs as globals. They can be Number, Text, Colour, Alpha, Time, Point, Yes or no, or Tags.

- **Limited.** The code has the basic functions and `string`, `table`, `math` and `bit`, and nothing else. It has no `io`, `os` or `require`, so it can't read files or reach the network.
- **Sandboxed.** It runs in a helper of its own, inside an operating-system sandbox with no network access. Where the system can't provide the sandbox, Lua nodes still run, with the same limits.
- **Deterministic.** The same graph and lines always give the same output. There is no `math.random`: use the **Random** node, which draws from the graph's seed. Nothing a row of code sets carries over to the next unit or line.
- **Ten seconds.** If a line's Lua takes longer than 10 seconds, it is stopped, and Apply writes nothing.

Lua nodes need the same trust as [templates](/en/docs/karaoke/template-editor#trusting-a-file). When a graph has a Lua node, the mode says *This file's node effects run Lua code with your rights. Preview them if you trust the file.* Press **Preview** to trust the file. It is one choice per open file: trusting it here or in the Template editor covers both. A graph without a Lua node never asks.

## Nodes from plugins

A [plugin](/en/docs/plugins/using-plugins) can add nodes of its own. They are listed in **Add node** under the plugin's name, and work like Lua nodes:

- **The plugin is the trust.** Installing the plugin and turning it on is all its nodes need. They don't ask for the file's trust, which is still needed for the file's own Lua nodes.
- **The same sandbox.** They run in the same helper as Lua nodes, with the same limits and the same ten seconds.
- **Only the plugin's code.** A node's code always comes from the installed plugin's files. The graph keeps only which node it is and its fields, so code that a file carries for a plugin node is ignored.

When the plugin isn't installed, is turned off or revoked, or its files are no longer signed with the key it had when you installed it, the node stays in the graph. It shows a problem naming the plugin, such as *comes from the plugin "Zigzag", which is turned off or not trusted*, and Apply writes nothing.

A graph with a plugin node can't be [exported as template lines](#exporting-as-template-lines): the node *runs in HikariSub's Lua helper, not in the templater*.
